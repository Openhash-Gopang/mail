# 첨부서류 카탈로그 갱신 방법

`attach-catalog.js` 가 서류 이름 → 발급 기관을 정한다(AI 호출 없음). 규칙은 위에서부터 처음 맞는 것이 이긴다.

| 종류 | 뜻 | 서류 화면 |
|---|---|---|
| agency | 공공기관 사이트에서 발급 | "도우미가 가져오기" 버튼, 도우미가 그 사이트를 바로 연다 |
| thirdparty | 회사·병원·학교 등 개별 기관 발급 | 버튼 없음 |
| user | 사용자가 만들거나 가진 자료 | 버튼 없음 |
| unknown | 카탈로그에 없음 | 예전처럼 도우미 AI 가 판단 |

입력(input): `none` 은 본인 명의로 바로 발급(AI 없이 즉시 시작), `ask` 는 대상(법인 이름·주소·사건번호)을 물어야 하므로 사이트·로그인을 먼저 열고 대상은 나중에 전한다.

## 새 서류 양식을 추가했을 때
1. `node scripts/catalog-coverage.mjs --forms <navi-pro>/docs/forms` — 분류되지 않은 이름이 빈도순으로 나온다. 전체 빈도표와 분류 근거(규칙·낱말)는 `node scripts/attach-report.mjs --forms <navi-pro>/docs/forms --out attach_all.csv`.
2. 상위 항목을 `attach-catalog.js` 의 규칙 배열에 추가한다(구체적인 규칙을 위에). 새 기관이면 `AGENCIES` 에도 넣는다. 도우미는 모든 https 사이트를 다루므로 허용 사이트 목록에 도메인을 넣을 필요가 없다.
3. `node --test tests/naviweb-agent.test.mjs` — 카탈로그 시험(기관 정의·정규식)이 통과해야 한다.

## 주기 점검(월 1회 권장)
- `node scripts/catalog-check.mjs` — 기관 사이트 주소가 살아 있는지. 실패하면 주소·절차를 확인하고 `VERIFIED` 날짜를 갱신한다.
- 사용자 제보("이 서류 기관이 달라요")가 들어오면 규칙을 고친다.

현재 규칙은 사람이 검토하기 전의 초안이다(`reviewed:false`). 기관 화면·절차는 바뀔 수 있다.

## 2026-11-08 v3 — 사유 코드·형태, 법원 서류
`classify()` 는 종류(kind) 외에 사유 코드(`reason`)와 형태(`form`)를 돌려준다.

| reason | 뜻 | 서류 화면에서 |
|---|---|---|
| AGENCY | 기관 발급 (이미 가진 경우 올리기도 허용: `upload:true`) | 가져오기 버튼 |
| THIRD_PARTY | 개별 기관·사람이 발급 | 누구에게 어떻게 요청하는지 안내 |
| USER_OWNED | 사용자가 작성·준비 | 올리거나 작성 안내 |
| USER_HELD | 사용자가 가진 서류의 사본·원본 | 올리기 안내 |
| GENERIC | 통칭 이름(“변경사실을 증명하는 서류” 등) — 서식 문맥이 있어야 서류를 정할 수 있음 | 도우미가 무엇인지 물음 |
| UNKNOWN | 규칙 없음 | 도우미 AI 가 판단 |

- `form` 은 사본 / 원본 / 정본. 이름에서 사본·원본·부수·접두어(신청인·대표자·기존 등)를 뗀 뒤 분류한다. 정본은 사본과 합치지 않는다.
- 집행권원·판결문·결정문·재판서·사건기록은 법원(전자소송) 서류다(예전에는 사용자 자료로 분류되어 버튼이 없었다). 송달료·인지도 전자소송이다.
- 주민등록 규칙은 `주민등록` 낱말이 있어야 한다(‘등본’만으로는 걸리지 않는다. 법원 결정문 등본·등록부 등본이 정부24 주민등록으로 분류되던 문제).
- 신청서·동의서·의뢰서·위임장은 기관 서류가 아니라 사용자가 쓰는 양식이다. 영수증(송달료·인지)과 목록(사건기록목록)도 기관 서류로 보지 않는다.
- `unverified:true` 규칙은 이름만 보고 정한 후보다. 발급 방법·수수료는 조사 후 확정한다.
- 서류 화면 제한(식 20개·200자)은 `patterns()` 가 지킨다. 묶음마다 양식 제외 앞머리가 붙으므로 규칙을 추가할 때 `tests/attach-catalog.test.mjs` 가 길이·개수를 확인한다.

## 2026-11-08 v4 — 조사 결과 반영, 모든 사이트 허용
- **도우미는 모든 https 사이트를 다룬다.** 사이트 허용 목록은 없다. 지키는 것은 사이트가 아니라 동작이다: 로그인·인증·결제·보안문자는 사용자가 직접(handoff), 주민등록번호·비밀번호·카드번호는 입력하지 않고(deny), 제출·발급·전송·삭제는 확인(confirm)을 받는다.
- 홈택스 서류는 서류별 규칙으로 나뉜다: `biz-reg`(사업자등록증), `biz-closure`(폐업·휴업사실증명), `withholding`(원천징수영수증), `tax-invoice`(세금계산서, 확인 전 `input:'ask'`), `income-cert`(소득증명원·납세사실).
- 제조사·임대사업자·거래처 등 **타인 회사의 사업자등록증**은 기관 서류가 아니라 사용자 자료다.
- 제적등본은 정부24가 아니라 대법원 전자가족관계등록시스템(`efamily`)에서 발급한다. 법인 인감증명서는 등기소(`corp-seal`).
- `paid:true` 는 결제가 드는 서류(특허증·등록원부)다 — 도우미는 결제 전에 멈추고 금액을 보여 준다. `fallback` 은 가져오기가 안 될 때의 대체 경로 문구다.
- `REASONS` 에 실행 중 사유(`SYSTEM_OUTAGE` 기관 시스템 장애, `FETCH_FAILED` 가져오기 실패)를 더했다. 서류 화면과 관리자 보고함이 쓴다.
- 알려진 한계: 타인(채무자 등)의 주민등록등본은 온라인 발급이 본인·세대원으로 제한된다. 도우미가 “본인·세대원 서류인가요?”를 물어야 하며, 규칙으로는 구분하지 않는다.
- 수수료·절차의 근거와 확신도는 조사 기록(`attach_research_batch*.csv`)에 있다. 등기사항증명서 수수료는 인상 예고(열람 1,100원·발급 1,400원, 시행 예정 2026-11-23)가 있으니 시행 뒤 다시 확인한다.

## 2026-11-08 조사 결과 반영
- 기관 서류 조사 기록은 `docs/attach-research/` 에 있다: `attach_agency_docs.csv`(기관 서류 713종, 건수순·조사 상태), `attach_research_batch1~6.csv`(서류별 경로·수수료·인증·확신도·출처). 카탈로그의 `note`(수수료·절차 안내)·`conf`(확신도: 높음·중간·낮음·미조사)는 이 기록에서 옮긴 것이며, 도우미가 가져오기를 시작할 때 안내로 보여 준다. 확신도가 낮은 항목은 공식 사이트 화면으로 다시 확인한다.
- `explain(label)` 은 서류 화면이 “도우미가 가져오기” 버튼이 없는 첨부서류에 이유를 보여 줄 때 쓴다. 서류 화면이 `{ type: 'navi-doc-slot-reason', label }` 을 보내면 호스트가 `navi-doc-slot-reason-result`(reason·text·note·conf·paid·fallback)로 답한다.
- `who` 는 개별 기관 발급 서류의 요청처(소속 회사·진료받은 병원 등)다.
- 도우미가 가져오지 못하면 호스트가 서류 이름·사유 코드(`FETCH_FAILED`·`SYSTEM_OUTAGE`)·규칙만 관리자에게 자동 보고한다(`feedback-kit.js` 의 `autoReport`, 같은 기기·같은 날·같은 서류·같은 사유는 한 번). 주간 집계와 `admin.html` 의 “제보 보고함”에 모인다.
- 날짜가 정해진 재확인은 `AGENCIES[].reviewAfter` 에 적고 `node scripts/catalog-check.mjs` 가 알려 준다(예: 등기사항증명서 수수료 인상 예고, 2026-11-23).
- 정부24는 정기 점검으로 20시간 이상 서비스가 중단된 적이 있다(공식 공지). 가져오기 실패가 이 때문이면 `SYSTEM_OUTAGE` 로 보고되고 사용자에게 점검 가능성을 알린다.
